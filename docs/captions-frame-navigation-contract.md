# Captions and frame navigation

- Interaction feedback marks the frames that may gain or lose items and highlights items carried by a frame. During a drag, moving toward the canvas edge pans the view and keeps the grabbed item under the pointer. Disabling interaction feedback turns off edge panning. Caption snapping has its own switch.
- Caption snapping defaults to on when its preference is absent. Canvas options live in browser storage scoped to the profile and site origin, separate from the board. Loading preferences leaves the saved value alone. Earlier builds saved both options whenever either changed, so every stored `captionSnap: false` is retained.
- An image may have one attached caption. An attached caption shares the image's frame ownership and follows the image when it moves. Legacy captions start with their saved coordinates and use their existing edge alignment when a placement changes.
- With caption snapping enabled, dragging upright text near an available image edge previews its landing. The caption stores its center as a fraction of the edge length, including the endpoints, and uses that fraction when the image resizes. The displayed upright bounds of a rotated or cropped image determine its edges. Ctrl or Cmd at release suppresses the snap. Interrupted gestures restore the previous scene.
- An attached caption may have a solid background color. An absent color draws no box. Attachment edits, background changes and transforms use the normal undo and save lifecycle.
- A frame jump moves only the viewport. Several jumps share the original return point. A no-op jump leaves the return point and save state alone. Returning restores the original zoom and pan exactly. A changed manual view or canvas resize clears the return point.
- Frame tour uses a detached scene captured at entry, with selected frames taking precedence over visible frames. Previous, Next and Esc operate inside the tour. Entering or leaving a tour creates no board edit, selection change, viewport change, history entry or save.
