# Engineering reference

Read the project map before working in unfamiliar code, the lifecycle checklist before changing interactions or persistence, and the review rules when reviewing those changes. See [expected behaviour](expected-behavior.md) for feature contracts and [AGENTS.md](../AGENTS.md) for verification and working rules. Paths in code spans are relative to the repository root.

## Project shape

- One npm package (ES modules, strict TypeScript): React 19 for the chrome, Fabric.js 7 for the canvas, Vite for dev and build, Vitest (jsdom) for unit tests, Playwright for real-browser tests. There is no backend and no `.env`.
- Fabric is pinned at 7.4.0 by the lockfile, and `FrameCanvas` overrides Fabric internals. Do not change dependencies unless a task genuinely requires it; say why if you do.
- `src/model/` is pure, with no Fabric or DOM dependency: document types and validation (`types.ts`, `doc.ts`), frame ownership rules, scale limits and hit geometry (`frames.ts`), the canonical form of text formatting, how heading levels carry across an edit, what the formatting controls do to a range, a caret or a whole box, and the typing-shortcut matcher (`richText.ts`), crop, Fit and Fill geometry (`crop.ts`), `history.ts`, `layers.ts`, `viewport.ts`, `id.ts`.
- Only `src/editor/` imports Fabric, and `src/editor/Editor.ts` is the only part the UI talks to: it owns the canvas, history, assets and autosave and exposes an immutable state snapshot. `FrameCanvas.ts` holds the frame hit-testing, Shift-click and marquee rules; `cropLayer.ts` draws crop mode's overlay from the same handle geometry that is hit; `frameLayer.ts` the one geometry used both to draw and to hit a frame's outline and label; `objects.ts` converts between records and Fabric objects, including a text's formatting and Fabric's per-character styles, and sets the lock flags; `fonts.ts` maps font ids to CSS font chains; `assets.ts` decodes images and keeps their original bytes for the session; `layerList.ts` derives the layer list.
- `src/persistence/` is the IndexedDB store (`boardStore.ts`), the save status machine (`autosave.ts`) and fail-closed loading (`hydrate.ts`). `src/input/shortcuts.ts` maps keys to actions; `resolveEditingShortcut` there is the only resolver for keys pressed while a text is edited, and `typedCharacter` the only judge of whether a key typed a character that can complete a typing shortcut. `src/ui/` is React chrome only (`LayerPanel.tsx` is the layer list).
- Test support: `src/editor/testing/` (a fake Fabric; a driver that replays by hand the event sequence of Fabric's mouse handlers, which is an imitation and not evidence of Fabric's behaviour; a fake store and assets), `src/persistence/testing/legacyStoreV1.ts` (a frozen copy of milestone 1's storage code; never modernize it), and `e2e/helpers.ts` (seeding and reading IndexedDB).
- Working files use LF. If Git on the machine has `core.autocrlf=true`, `git stash` and checkouts rewrite files with CRLF; tools that match text literally must tolerate that.

## Check lifecycle behaviour while implementing

- For any change to gestures, selection, text editing, saving or loading, identify the failure cases while designing and testing it, not afterwards:
  - a gesture interrupted by Esc, by the window losing focus, by a reload, or by the board going read-only;
  - a second mouse button pressed or released mid-drag, and a release that never arrives;
  - the autosave debounce firing, or a save already in flight, during a gesture;
  - an image import that finishes decoding during a gesture;
  - another tab having written the board, or pruned its image bytes;
  - every way of leaving a text edit (Esc, clicking elsewhere, clicking another object, Shift-click, a toolbar or panel button), remembering that typing is saved as it happens while history is recorded when the edit ends;
  - undo and redo straight afterwards, and input before the stored board has finished loading.
- Exercise the cases that apply with focused tests before asking for review. Independent review is a second check, not the first time these cases are considered. Documentation-only changes do not need them.

## Code review rules

- Flag: settling a gesture, or removing an object, inside a Fabric callback; a frame gaining a member by being moved, resized or drawn; an owner lost to a frame that merely overlaps it; a member moved twice; contents stretched or moved by a lone frame resize; a per-member limit inside a proportional scale or in serialization; a canvas state the records cannot store; a heading level read from character sizes after a text change; a formatting write that bypasses `applyTextFormatting`/`writeTextFormatting` or uses `setSelectionStyles`; a formatting control that takes focus from, or ends, a text edit, or loses its selected range; a key claimed in a text edit with Alt or Shift held, during composition, or not from the edited text; a typing shortcut that fires on pasted, dropped or composed text, or that changes the object without its hidden textarea; Backspace claimed outside the moment straight after a shortcut fired; bold stored inside a heading line; a pending mark that outlives a caret move or the edit; a save that can see a half-finished gesture; a click or a read-only board that writes; selecting from the layer list that records history or saves; a selection that contains a locked item and anything else; a command or gesture that edits a locked item; a locked item reachable by a press, a marquee, Select all or Shift-click; `locked: false` or an explicit `undefined` written to storage; a lock change that is not a history step; a save that can see an open crop; a command that runs against the temporarily un-cropped image; a crop applied with movement of the kept pixels; a `crop` object shared between snapshots; a flat comparison of nested record values; a Fit or Fill that is not idempotent; a save scheduled or run after dispose; a crop rounded so that it reaches outside the image; two different whole-image decisions; a replacement applied to a target chosen when the file arrives rather than when the button was pressed; a replacement that moves or resizes the box, or re-decides ownership; a document written with a new asset before (or without) its bytes; a load that rewrites the board row; a save without the revision check; a test that reaches the owner's board or a live dev server; a test that cannot fail.
- Safe paths: deferred settlement; ownership decided by the pure rules in `src/model/frames.ts`; one scale factor per gesture; records as the source of truth; token-checked transactional writes; isolated browser contexts with seeded storage.
- Traps that have already cost time here:
  - The fake's multi-selection holds its members' absolute results, so it cannot detect a double move or wrong group geometry. Cover those in `e2e/`.
  - Removing an object inside Fabric's `text:editing:exited` makes Fabric throw afterwards. Defer the removal.
  - Objects cannot be flipped, so a handle dragged past its anchor stops at the last accepted scale. A test cannot reach a minimum size by dragging through the anchor; drag to just short of it.
  - Button names overlap ("Select" and "Select with contents", "Frame" and "Delete frame", "Lock" in the inspector and on every layer row, "Lock" and "Unlock", "Heading 1" and the like): use exact role locators in Playwright.
  - In Fabric 7.4, Ctrl+End in a text goes to the end of the line, not of the text, and End with a selection only collapses it: a test that wants the end of the text uses Ctrl+A then ArrowRight.
  - Fabric fires `text:selection:changed` before it stores the new selection in some paths (`IText.mjs` `_updateAndFire`): read the selection in a microtask, not in the handler.
  - The editor unit tests fake only `setTimeout`; `fake-indexeddb` runs on `setImmediate`, so real store writes need real macrotasks to finish.
