# Engineering reference

Read the project map before working in unfamiliar code, the lifecycle checklist before changing interactions or persistence, and the review rules when reviewing those changes. See [expected behaviour](expected-behavior.md) for feature contracts and [AGENTS.md](../AGENTS.md) for verification and working rules. Paths in code spans are relative to the repository root.

## Project shape

- One npm package (ES modules, strict TypeScript): React 19 for the chrome, Fabric.js 7 for the canvas's selection, handles, hit testing and gestures, ProseMirror (the bare `prosemirror-*` packages) for editing text, Vite for dev and build, Vitest (jsdom) for unit tests, Playwright for real-browser tests. There is no backend and no `.env`.
- Fabric is pinned at 7.4.0 by the lockfile, and `FrameCanvas` overrides Fabric internals. Do not change dependencies unless a task genuinely requires it; say why if you do.
- `src/model/` is pure, with no Fabric or DOM dependency: document types and validation (`types.ts`, `doc.ts`), frame ownership rules, scale limits and hit geometry (`frames.ts`), the canonical form of text formatting, how heading levels carry across an edit, what the formatting controls do to a range, a caret or a whole box, and the typing-shortcut matcher (`richText.ts`), the rich form of a text (`blocks`, fixed height, paper): its strict validation, canonical form, conversion to and from the compact form, what counts as blank, and which rich fields need the version 3 fence or this build cannot edit (`textDoc.ts`), paper's padding, the words' own box inside the sheet and the Paper toggle's centre-keeping geometry (`paper.ts`), crop, Fit and Fill geometry (`crop.ts`), `history.ts`, `layers.ts`, `viewport.ts`, `id.ts`.
- Only `src/editor/` imports Fabric or ProseMirror, and `src/editor/Editor.ts` is the only part the UI talks to: it owns the canvas, the scene layer, history, assets and autosave and exposes an immutable state snapshot. `FrameCanvas.ts` holds the frame hit-testing, Shift-click and marquee rules; `cropLayer.ts` draws crop mode's overlay from the same handle geometry that is hit; `frameLayer.ts` the one geometry used both to draw and to hit a frame's outline and label; `objects.ts` converts between records and canvas objects (the transparent proxies, with their card and picture data) and sets the lock flags; `fonts.ts` maps font ids to CSS font chains; `assets.ts` decodes images and keeps their original bytes for the session, and `stillImage.ts` gives an image that can animate a first-frame still; `layerList.ts` derives the layer list.
- What is drawn: `sceneLayer.ts` is the scene layer under the canvas (frame paper, images and text cards in stacking order; a card's static HTML, its measured height and minimum width, the no-wrap spans that keep a click-created box wrapping between words only, offscreen culling; fixed heights: each card's remembered scroll position, the fades and the scroll thumb); `domScene.ts` keeps it in step with the canvas's proxies inside Fabric's `before:render` and sizes the text proxies from their cards at the flush points; `renderFrameBitmap.ts` draws a frame's preview from the same cards (text as SVG `foreignObject`).
- The wheel: `wheelGesture.ts` decides who a wheel gesture belongs to (pure: `pickWheelOwner`, `WheelLatch`). `WHEEL_LATCH_MS` there (180 ms) is the value to tune if a trackpad flick splits in two (its glide panning the board after a box reached its end).
- Text: `textAdapter.ts` is the seam for everything the editor does with text (`DomTextAdapter`); `textSession.ts` is one edit (the ProseMirror state, its single guarded `dispatch`, the mounted view, paste, IME, in-edit undo); `textRules.ts` the text rules as ProseMirror commands and pure functions (headings, marks, pending choices, typing and block shortcuts and their revert, keys, list, quote, code and divider commands, plain paste, where a paste of blocks lands: `pasteBlocks`); `pasteHtml.ts` reads pasted HTML into blocks in an inert document, against an allowlist (`htmlToBlocks`, `DROPPED`); `textSchema.ts` the document schema (with lists, checklists, quotes, code blocks and dividers), its lines (every textblock in order) and its conversion to and from the compact record and `blocks`.
- There is one renderer. The Fabric renderer it replaced (Fabric's own text boxes and images, `DrawnTextbox.ts`, `framePreview.ts`, the per-character style code) was deleted in Slice 2d-ii; Fabric.js stays for the canvas, the proxies, selection chrome, frame outlines and gestures.
- Frozen references keep the tests that compared the app with the Fabric renderer independent of the app. `e2e/fabric-reference/<spec>/` and `src/editor/testing/fabric-reference/<test file>.json` hold, per test, what the Fabric renderer gave for its script (scenes, history, state, saved boards, carets, measured ink and box sizes, lift-shadow screenshots), read by `e2e/fabricReference.ts` and `src/editor/testing/fabricReference.ts`. Each file records its provenance (the commit whose app source was the Fabric renderer, the command, the browser or runtime, the platform) and each entry a hash of the test's inputs, so a test whose board or script changes fails instead of comparing with a reference recorded for something else. The hash catches a changed board, options or declared script, not every change to how a script is performed: it covers what the test hands the helper, and some tests hand it a prose description of what they do (`e2e/dom-preview.spec.ts`, `e2e/interleaving.spec.ts`) or call shared helpers whose behaviour it does not see. So the test code that performs a paired script must not be edited without re-recording its reference (see the next point), not even in a way that leaves its hash alone. They were recorded mechanically by running the Fabric renderer (`FABRIC_REFERENCE=record`), three times with identical results, and checked against live runs (`FABRIC_REFERENCE=check`). Both modes work only in commit `03fa4c2`, the last commit in which the Fabric renderer exists; its app source is that of `9e73b09`, the commit the files name as recorded from. Never edit a reference by hand. Re-recording one as the Fabric renderer gave it means checking out `03fa4c2` (in a separate worktree), changing the test there, and running, for a browser spec, `FABRIC_REFERENCE=record npx playwright test e2e/<spec>.spec.ts` (for example `e2e/interleaving.spec.ts`), or, for a unit test, `FABRIC_REFERENCE=record npx vitest run src/editor/<test>.test.ts` (`textRules`, `proxies`, `textAdapter` or `Editor.domFeatures`); the unit files name the command with a literal `<file>` in its place. `FABRIC_REFERENCE=check` in place of `record` runs the Fabric renderer and compares it with the stored references without writing. A test whose script must change and cannot be re-recorded that way is re-recorded from the app, as the next point says. They were recorded in Chromium on Windows; measured text (wraps, ink, box sizes) can differ on another platform's fonts.
- A reference may be re-recorded from the current app (owner decision, 2026-11-26). The references began as the Fabric renderer's output; `03fa4c2` proved the app equal to them, so from then on they are snapshots of settled behaviour, not a record that only Fabric may write. When a comparison fails, first decide whether the app regressed, and if it did, fix the app. If the cause is a browser or font update, or a change to behaviour or to a script that the owner approved, re-record the affected references from the current app. Do that in a commit of its own that says what changed and why, read the diff to confirm that only the expected values moved, and set the file's `recordedFrom` to the app commit so that nobody reads it as Fabric's output. The helpers (`e2e/fabricReference.ts`, `src/editor/testing/fabricReference.ts`) only read today: recording from the app needs a record mode added to them, to be built the first time it is needed. Their header comments and each reference file's `about` line still state the older never-record-from-the-app rule; this point supersedes them. The frozen copy of the Fabric text code (`src/editor/testing/fabricTextOracle.ts`) is separate and stays.
- `e2e/text-engine-parity.spec.ts` keeps a live oracle instead: `src/editor/testing/fabricTextOracle.ts`, a frozen copy of the Fabric renderer's text code run on real Fabric text boxes (its IME oracle depends on which session commands a composition refused, which recorded values could not follow). Never modernize it (like `legacyStoreV1.ts`), and never import it from the app.
- `src/persistence/` is the IndexedDB store (`boardStore.ts`), the save status machine (`autosave.ts`) and fail-closed loading (`hydrate.ts`). `src/input/shortcuts.ts` maps keys to actions; `resolveEditingShortcut` there is the only resolver for keys pressed while a text is edited, and `typedCharacter` the only judge of whether a key typed a character that can complete a typing shortcut. `src/ui/` is React chrome only (`LayerPanel.tsx` is the layer list).
- Test support: `src/editor/testing/` (a fake Fabric; a driver that replays by hand the event sequence of Fabric's mouse handlers, which is an imitation and not evidence of Fabric's behaviour; a fake store, assets and card measurer, and `stubTextLayout`, the jsdom stubs the text engine's view needs; `editing.ts`, which drives a text edit through the edit session; `textHarness.ts`, a session without an editor; the frozen references and oracle above), `src/persistence/testing/legacyStoreV1.ts` (a frozen copy of milestone 1's storage code; never modernize it), and `e2e/helpers.ts` (seeding and reading IndexedDB; `editedText`, the text being edited, its selection and focus as the page shows them; `screenPixels`, composited screenshots of the board for pixel checks).
- Working files use LF. If Git on the machine has `core.autocrlf=true`, `git stash` and checkouts rewrite files with CRLF; tools that match text literally must tolerate that.

## Check lifecycle behaviour while implementing

- For any change to gestures, selection, text editing, saving or loading, identify the failure cases while designing and testing it, not afterwards:
  - a gesture interrupted by Esc, by the window losing focus, by a reload, or by the board going read-only;
  - a second mouse button pressed or released mid-drag, and a release that never arrives;
  - the autosave debounce firing, or a save already in flight, during a gesture;
  - an image import that finishes decoding during a gesture;
  - another tab having written the board, or pruned its image bytes;
  - every way of leaving a text edit (Esc, Tab, clicking elsewhere, clicking another object, Shift-click, a frame label, a toolbar or panel button), remembering that typing is saved as it happens while history is recorded when the edit ends, and Undo and Redo inside the edit (keys and toolbar buttons) before and after leaving it;
  - undo and redo straight afterwards, and input before the stored board has finished loading.
- Exercise the cases that apply with focused tests before asking for review. Independent review is a second check, not the first time these cases are considered. Documentation-only changes do not need them.

## Code review rules

- Flag: settling a gesture, or removing an object, inside a Fabric callback; a frame gaining a member by being moved, resized or drawn; an owner lost to a frame that merely overlaps it; a member moved twice; contents stretched or moved by a lone frame resize; a per-member limit inside a proportional scale or in serialization; a canvas state the records cannot store; a heading level read from character sizes after a text change; a change to the edited text that does not go through the edit session's `dispatch`, or a record written from it in anything but the canonical compact form; a formatting control that takes focus from, or ends, a text edit, or loses its selected range; a key claimed in a text edit with Alt or Shift held, during composition, or not from the edited text; a typing shortcut that fires on pasted, dropped or composed text, or through ProseMirror's own input or paste rules; Backspace claimed outside the moment straight after a shortcut fired; an in-edit Undo or Redo that leaves the edit or steps board history; the session dispatching, reading or re-rendering while an IME composition is open; pasted HTML parsed into the live document rather than an inert one; a card or item placed from anything but its proxy's matrix; a card measured with `getBoundingClientRect()` (it is the rotated, zoomed bounding box), or resized by a `ResizeObserver`; bold stored inside a heading line; a pending mark that outlives a caret move or the edit; a save that can see a half-finished gesture; a click or a read-only board that writes; selecting from the layer list that records history or saves; a selection that contains a locked item and anything else; a command or gesture that edits a locked item; a locked item reachable by a press, a marquee, Select all or Shift-click; `locked: false` or an explicit `undefined` written to storage; a lock change that is not a history step; a save that can see an open crop; a command that runs against the temporarily un-cropped image; a crop applied with movement of the kept pixels; a `crop` object shared between snapshots; a flat comparison of nested record values; a Fit or Fill that is not idempotent; a save scheduled or run after dispose; a crop rounded so that it reaches outside the image; two different whole-image decisions; a replacement applied to a target chosen when the file arrives rather than when the button was pressed; a replacement that moves or resizes the box, or re-decides ownership; a document written with a new asset before (or without) its bytes; a load that rewrites the board row; a save without the revision check; a test that reaches the owner's board or a live dev server; a test that cannot fail.
- Safe paths: deferred settlement; ownership decided by the pure rules in `src/model/frames.ts`; one scale factor per gesture; records as the source of truth; token-checked transactional writes; isolated browser contexts with seeded storage.
- Traps that have already cost time here:
  - The fake's multi-selection holds its members' absolute results, so it cannot detect a double move or wrong group geometry. Cover those in `e2e/`.
  - Removing an object inside a Fabric callback makes Fabric throw afterwards. Defer the removal: a blank text left by an edit is hidden at once and removed in a microtask.
  - The scene layer places every item from its proxy's matrix (`calcTransformMatrix` and the viewport transform) inside `before:render`, so DOM and canvas chrome move in the same frame. Reading the item's own geometry back, or placing it after the frame, makes the two drift apart during a drag.
  - A card's height and minimum width are read from its untransformed layout (`getComputedStyle` height, an offscreen probe), never `getBoundingClientRect()`, which gives the bounding box after zoom and rotation. Cards have no `ResizeObserver`: sizes are taken synchronously at the flush points, and a late font load lays cards out again only when no gesture is unsettled, without touching ownership, history or the save state.
  - While a text is edited, its card's children belong to ProseMirror: the layer updates only the card's geometry and box styles and renders it again when the edit ends. No ancestor of a card may scroll (the browser scrolls one to follow the caret): `.scene-layer` is `overflow: clip`.
  - ProseMirror ignores a caret move to the very start of a text for 200 ms after its editor gains focus (`DOMObserver.flush`, prosemirror-view 1.43); the session takes a key's own move as the selection. A ProseMirror upgrade must re-run `e2e/text-engine-parity.spec.ts`'s selection-key test.
  - A line is a textblock, not a top-level block: offsets, line levels, canonical runs, no-wrap ranges and the measurer all walk `textblocksOf`. Code written against `doc.forEach` works for a text without blocks and silently breaks inside a list.
  - The fake Fabric models state machines, not layout, and jsdom lays nothing out: card sizes in unit tests come from `FakeCardMeasurer`. Wrapping, caret placement, selection and IME are accepted only on real-browser evidence.
  - Objects cannot be flipped, so a handle dragged past its anchor stops at the last accepted scale. A test cannot reach a minimum size by dragging through the anchor; drag to just short of it.
  - Button names overlap ("Select" and "Select with contents", "Frame" and "Delete frame", "Lock" in the inspector and on every layer row, "Lock" and "Unlock", "Heading 1" and the like): use exact role locators in Playwright.
  - Caret keys follow the browser in the edited text. The paired scripts were recorded on the Fabric renderer too (whose Ctrl+End went to the end of the line, and whose End with a selection only collapsed it), which is why they reach the end of a text with Ctrl+A then ArrowRight: changing that changes their inputs, and their frozen references no longer apply.
  - DOM text is drawn with the browser's subpixel smoothing, which puts orange and blue fringes on dark text: a pixel check that counts "red" must require a clear lead of red over green and blue.
  - The editor unit tests fake only `setTimeout`; `fake-indexeddb` runs on `setImmediate`, so real store writes need real macrotasks to finish.
  - A fixed-height card's scroll must be set and read in its own units: through `SceneLayer.toCard` (the viewport and the card's matrix), never ProseMirror's own scrolling, which moves by page pixels and walks up to the window (`handleScrollToSelection` in `textAdapter.ts` takes it over).
  - Playwright launches Chromium with `--hide-scrollbars`: a test about scrollbar width must turn that off (`e2e/card-height.spec.ts` does, for the whole file).
  - New text boxes get paper, which would change the meaning of every test written before it. Development builds read `localStorage['yuriful:test:bare-new-text'] === '1'` (`BARE_NEW_TEXT_KEY` in `Editor.ts`) to make new boxes bare; Vitest sets it in `src/editor/testing/bareNewText.ts`, and `playwright.config.ts` sets it through `storageState` for every browser context, including `browser.newContext()`. A test about paper clears it: `e2e/paper.spec.ts` uses an empty `storageState`, and `Editor.paper.test.ts` removes the key and restores it. Production builds never read it.
  - The paper look is the `--paper-*` properties in `:root` (`src/styles.css`), and frame previews read the same properties (`paperLook` in `renderFrameBitmap.ts`). `--paper-shadow` must never be `none`: it is joined with `--paper-edge` in one `box-shadow` list, and a list containing `none` is invalid, so the browser drops the whole declaration, edge included. Use `0 0 #0000` for no shadow, and keep the shadow within `PAPER_BLEED` (16 px), or previews cut it off.
  - Paper sizes are outer: anything that measures or lays out words must go through `innerText`, and anything that reports a size back adds the padding (`paperWidth`, `measureRecord`, `minWidthOf`). `innerText` also holds a fixed height to `minFixedHeight`, so a record below it is drawn at it without being rewritten. Card coordinates (`SceneLayer.toCard`) start at the sheet's corner, not the words': subtract the padding before comparing with the body's size (`revealSpan` does).
  - A turned object's matrix decomposes (`util.qrDecompose`) to a scale a few units in the last place off 1. Never test a decomposed scale for exact equality with 1: `toRecord` reads one within `UNIT_SCALE_TOLERANCE` of 1 as 1 (`objects.roundTrip.test.ts` builds and reads hundreds of turned records with real Fabric; the editor unit tests' fake Fabric would not show it).
  - A margin press must pick the line before the point: the nearest point inside the words' whole box, at the press's height, can sit in a list's indentation, which ProseMirror resolves to a position between blocks and so to the line above (`pointOnNearestLine`).
  - A code block's `code` has `line-height: 0`; read a code row's line height from its `pre`.
  - Chrome hit-tests white space hung past a wrapped row as the paragraph, even in the sheet's margin: decide "inside the words" from the press's position, not `event.target`.
  - `e2e/paper-margins.spec.ts` is seeded (`PAPER_SEED`) and computes its expectations from character rectangles independently of `marginRows.ts`; keep it independent.
  - The paper margins are rounded to two decimals (`paperPad`) and `innerText` rounds the words' box the same way. A margin computed afresh from `fontSize × PAPER_PAD_*_EM` in each direction drifts by a hundredth per toggle, and a words' viewport that differs in the last bit counts as a changed fixed height, which sends a scrolled text back to its top.
  - Ctrl+Z while a panel field such as Font size has the keyboard is the field's own undo, not the board's: the field puts back its old value, which is a new command. A browser test that changes a value from the panel must undo with the toolbar's Undo button, or move the keyboard off the field first.
  - A CSS mask clips an element's outline and makes text on a turned card softer.
  - Paste conversion never goes through `handleTextInput` or the typing shortcuts: `handlePaste` hands the clipboard to `EditSession.paste`, which converts Markdown with `markdownToBlocks` and HTML with `htmlToBlocks`. ProseMirror's `transformPastedHTML` still runs for a drop, so the flat sanitizer stays. ProseMirror's own `pasteText` is a plain paste (`plain` true), like `Ctrl/Cmd+Shift+V`. A unit test that wants a converted paste calls `session.paste`; a browser test writes to the real clipboard and presses the real keys.
  - A paste of Yuriful's own copy depends on what the deletion just before it left: pasted over a selection, `pastedBlocks` reads the rest of the end item and list from that selection (`restOfEndItem`, `restOfEndList`); pasted at a caret, only from the session's `lastCut`, which a cut records and which counts only while the document and caret are exactly as the cut left them. `restOfEnd` gives the deepest block around the end line that holds more after it; `pasteBlocks` finds that rest by structure (the line after the caret's), never by a mapped position. Whether a paste goes back exactly where it came from (`backInPlace`) compares what the paste reads (`copyKey` of `htmlToBlocks`), not the HTML, which the browser rewraps. A change that makes the paste read its context from anywhere else (a mapped position, the clipboard) breaks cut-and-paste-back in ways only the seeded tests find: run `textBlocksRule.test.ts` with `PASTE_RULE_SEED` from 1 to 30.
  - A paste that changes no record is not a refusal: `paste()` tells them apart by the selection the paste left. Restoring the old selection after an accepted paste (the same characters put back) leaves the caret before them.
  - ProseMirror's `serializeForClipboard` moves wrappers that hold a single child out of the HTML into the `data-pm-slice` context, and wraps a bare `li` in a `ul`, so a copy of a list inside a quote loses the quote unless the slice is closed first (`clipboardSlice`, through `transformCopied`). A drag is serialized through the same `transformCopied`; `dragstart` marks it so its slice is left as it is. `data-pm-slice` is not Yuriful's: every ProseMirror editor writes it. Yuriful's own copy is recognised by `data-yuriful` (`YurifulClipboardSerializer`), and only that marker may unlock anything internal, such as fonts. `DOMSerializer.serializeFragment` calls itself for every node's content, so the serializer marks only in its outermost call; the marker's value (the copy's open edges) is handed over from `clipboardSlice` in a module variable set just before it runs.
